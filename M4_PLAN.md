## Recommended first deliverable

An ordinary service on a **native x86-64 Ubuntu Intrinsic simulation host** reads one allowlisted ICON part through the official SDK and exports its compact joint state over the existing SENSOR path. A separate operator endpoint receives the state through SRT, with no direct DDS route bypassing it.

The first CONTROL operation is deliberately narrow: **change this adapter's telemetry polling rate**, using the existing `SetMeasurementRateCommand` / durable generation contract. Proposed demonstration: 20 Hz → 10 Hz → 20 Hz, generation 0 → 1 → 2. This changes the adapter's schedule, not the Intrinsic controller frequency, hardware state, safety configuration or robot motion. Success proves the adapter's applied rate/generation and a subsequent real simulated-runtime status observation; it does not claim a native Intrinsic `ExecuteDiagnostic` method.

This is the recommended definition of M4's first low-impact diagnostic task. Its scope must be agreed at P0 before implementation. If a native mutating Intrinsic operation is required instead, stop at state-only delivery and prepare a separate typed-command/API design; do not disguise that operation as a rate command. State-only progress is independently reviewable but is not complete M4 acceptance.

## Boundaries and contracts

- **Topology:** Intrinsic simulation and its local SDK-facing adapter on the native host; a bounded adapter-to-local-ROS handoff; a separately supervised bridge/worker; SRT CONTROL/SENSOR to an isolated operator bridge/observer. Intrinsic service discovery, SDK credentials and operational RPCs remain local to the adapter. Record the real auth/TLS setup without claiming equivalence to SRT authentication.
- **Build:** start from bridge merge `87d97f0` and provider `52be7c86ee1f303cbb0c8718c364217e4dd97a36`. Rebuild the SDK and ROS components for the selected Intrinsic/Lyrical toolchain in new prefixes. Build both WAN peers against compatible Lyrical types; qualify type hashes and installed import closure. Private worker IPC v4 requires matched workers/supervisors. Do not load the accepted Jazzy binaries into an Intrinsic process or assume cross-distro CDR compatibility.
- **SENSOR:** use existing route 2 / `sensor_msgs/msg/JointState`, for one configured simulated part with 1–6 joints. Validate complete configured ordering, finite sensed positions and documented units; optional velocity/effort arrays are either wholly valid or empty. Reject oversize/extra joints or names rather than truncate; enforce the existing codec/message budget. Do not synthesize IMU data to fill unused route 1. A new status/perception wire type is deferred.
- **Time:** timestamp local acquisition at RPC start and retain RPC end, server uptime timestamp and observed server instance separately. Transport publication age is a conservative local-observation bound including RPC time, under the bridge clock model—not physical sampling age. Unknown server-to-host time correspondence stays unknown. Server restart or timestamp regression quarantines the old observation and advances the adapter instance epoch. Because the current bridge does not carry an arbitrary adapter epoch in JointState, supervision must also invalidate/requalify the bridge session (restart the owned bridge/worker when no existing safe hook applies) to flush old work. Do not invent an epoch-rotation API or republish a cached status as new data.
- **Work ownership:** one in-flight SDK read, one latest pending state per part/route, bounded handoff/result queues; no SDK/network/journal calls inside realtime callbacks or while holding the rate/config lock. Declare fixed queue/receipt/journal and gRPC response-size limits before the first build, so even an all-parts GetStatus response cannot create an unbounded application handoff. Slow RPCs skip/coalesce planned polls and expose counts; they must not accumulate unbounded work or trigger autonomous rate adjustment.
- **CONTROL:** reuse the current rate-command schema and original 5-second start budget; initially allow only 10/20 Hz in the integration service. Receiver start authorization and `ApplyMeasurementRate.start_deadline_ns` both precede effect. A durable adapter-owned ID/hash/config-generation record binds requested rate, original deadline, applied generation, source instance and observation proof. Duplicate same ID/hash returns the original result; changed payload conflicts with no new effect. Persist desired configuration and restore it on process restart without reexecuting a historical command.
- **Outcomes:** SUCCEEDED requires the applied rate/generation and an attributable post-change actual-runtime status observation before the response is committed. Before-effect expiry/rejection needs positive evidence; loss/timeout after possible application is UNKNOWN, not FAILED or a replay permit. A committed result lost on the wire is recovered by QUERY. No automatic retry, forced expiry or cancellation-to-nonexecution inference. RPC failures before any application remain distinct from uncertainty after application.

The adapter's application record and the bridge's command journal have distinct responsibilities. P2 must specify their ordering and crash windows explicitly; there is no assumed distributed transaction. Response proof records the snapshot digest/instance/timestamps locally; the existing rate result attests only rate/generation, not a new arbitrary Intrinsic result schema.

## Target repository layout and ownership

- `docs/`: architecture, API inventory, state/command contracts, realtime boundary, acceptance and handoff.
- `baselines/`: source/release/image/toolchain/RMW/type/auth/resource manifests and predeclared cases.

- `ros2/`: adapter package and simulation launch wiring, built for the selected Lyrical environment; both WAN peers rebuilt compatibly.
- `tests/`: deterministic offline/import/installed-contract checks, followed by separately authorized simulation fixtures.
- `evidence/`: immutable preparation/authorization/run/result/postflight records and public/local hash indexes; no credentials or automatic replay journals.

The integration repo owns this adapter, SDK mapping, runtime deployment and M4 evidence. The bridge repo owns generic transport/journal/worker behavior; any required semantic change belongs in a separate reviewed bridge PR, with a new build/qualification boundary. Provider changes remain separate and are not proposed. Keep initial review units small; stop to diagnose retained evidence rather than launch open-ended tracing or wider cohorts.

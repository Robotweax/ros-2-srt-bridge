## Target and observer protocol

The standalone Python fixture records its process PID/start_ticks and worker
TID/start_ticks before the host starts observing. All control files bind a fresh
calibration ID plus those identities; foreign/stale controls fail. The native
ARM64 observer joins only that owned target container's private PID namespace.
Two schema-valid, nonempty worker stacks are required before release authority
is written. The target then releases/joins the worker and keeps its parent alive.
The host requires either a complete-enumeration missing-task hint or explicit
per-task absence metadata matching that worker and the controlled release/join
phase. Only then can it authorize parent SIGINT. The original owned-child helper
retains its5s wait; exit0/unforced and controller success are mandatory.

The candidate's **confirmed_exit=false remains unchanged**. Controlled fixture
join is ground truth for this diagnostic protocol, not a general bridge task-exit
acceptance rule. Missing reads are never changed to readable stacks. This fixture
need not hit exit precisely between enumeration and stat; it validates native
access/schema/present identity and later absence visibility, not the exact N1
race, TID reuse or any campaign outcome.

Final assessment validates exact activation/exec/target identities, same boot/
zero time namespaces, monotonic ordered samples/read brackets, raw-versus-derived
metadata, task identities, stage sequence/times, controlled release/join/signal
order, schema integrity, footer populations and normal shutdown. Denied reads,
identity changes, truncation, incomplete populations and missing proof fail.
Post-SIGINT task availability is explicitly outside this fixture's qualification;
raw observations/counters remain retained. It is not the old blocked3s fixture
or a bridge shutdown timing/overhead equivalence claim.
